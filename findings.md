## Pipeline Findings
- Backend `train.run()` uses `train_test_split(..., test_size=0.2, random_state=42, stratify=y)` and trains a RandomForest pipeline from already processed `X.parquet` / `y.parquet`.
- `backend/app/ml/preprocessing.py` does not rebuild raw features; it only loads processed parquet files generated by `notebooks/01_eda_preprocessing.ipynb`.
- `notebooks/03_rf_svm_comparison.ipynb` / `_build_notebook_03.py` contains the learning-curve code. RF learning curve uses the full train set; SVM learning curve intentionally uses a subsample of 8000 records.
- Learning curve config in notebook 03: `LC_TRAIN_SIZES = np.linspace(0.1, 1.0, 6)`, `LC_CV = 3`, `LC_SCORING = "f1"`, `shuffle=True`.
- Saved learning-curve figure: RF train F1 is ~0.99 and CV F1 is already ~0.93 at the first point; SVM train/CV curves meet around ~0.93 quickly. This is consistent with strong post-start/full-course features, not with lack of target balance.
- Report text says current feature set has 16 numeric + 3 ordinal + 5 nominal columns, encoded to 47 model dimensions.
- Best RF holdout accuracy from a direct refit is `0.948`. Grouped impurity importances are led by `last_active_day` (`0.2521`), `num_submissions` (`0.1701`), `num_active_days` (`0.0962`), `mean_score` (`0.0797`), and `total_clicks` (`0.0756`).

## Likely Causes
- Main cause: the model is trained on full-course/post-outcome proxy features. `last_active_day`, `num_submissions`, full-course clicks, and assessment aggregates reveal whether a learner stayed active and submitted work across the whole course.
- Secondary cause: row-level random split allows the same `id_student` to appear in both train and test for different courses/presentations, making evaluation somewhat optimistic.
- Not a major cause: class imbalance, duplicate rows, or missing processed files after the user restored them.

## Dataset Correction: Day-125 Cutoff
- User selected prediction after course day 125.
- Regenerated processed data with only `studentVle.date <= 125` and `studentAssessment.date_submitted <= 125`.
- Removed `last_active_day` from processed features and metadata.
- New processed schema: `X.shape = (32593, 23)`, target counts `{0: 17208, 1: 15385}`, metadata `prediction_day = 125`, `n_features = 23`, numeric columns count `15`.
- VLE rows kept for cutoff aggregation: `6,750,733 / 10,655,280`.
- Assessment submission rows kept for cutoff aggregation: `94,517 / 173,739`.
- Backend feature loading and preprocessing were verified on the new schema; `last_active_day` is absent from `X` and from `numeric_cols`.
- Quick post-correction diagnostics: strongest single-feature AUCs are now `num_submissions=0.8340`, `num_active_days=0.8330`, `total_clicks=0.8079`; much lower than the previous full-course `last_active_day=0.9468`.
- Feature-group RF CV after cutoff: static-only F1 `0.6079`, click-only F1 `0.7656`, assessment-only F1 `0.8440`, full features F1 `0.8609`.
- Shuffled-stratified quick learning curve after cutoff starts at CV F1 `0.8422` for train size `2172` and ends at `0.8572`, so it should no longer plateau above `0.90` from the first point.
- Notebook 03 learning-curve CV was updated to a shuffled `StratifiedKFold` to match the main evaluation CV.
- Cutoff sensitivity check with train sizes from 2% to 100% of each CV training fold: day 30 CV F1 rises `0.7191 -> 0.7658`, day 60 `0.7725 -> 0.8068`, day 90 `0.7895 -> 0.8286`, day 125 `0.8251 -> 0.8585`.
- Smaller cutoffs do create a more visibly rising learning curve, but they also lower final performance and can still plateau. The currently configured notebook starts at 10% train size; using smaller train-size points such as 2% and 5% reveals the upward slope more clearly.
